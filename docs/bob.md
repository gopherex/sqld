# sqld-gen-bob — bob ORM from your sqld schema

`sqld-gen-bob` is an sqld code-generation plugin that drives
[stephenafamo/bob](https://github.com/stephenafamo/bob)'s generator from sqld's
IR `Catalog`. It gives you bob's full Go ORM — models, relationships with eager
loading, typed `where`/`loaders`/`joins`, optional factories — **using the same
canonical Go types `sqld-gen-go` emits**, so bob models and sqld query results
share one type per column and run on one `*pgxpool.Pool`.

This is the ORM ⊕ sqlc tandem: `sqld-gen-go` owns hand-written and dynamic
queries (and the leaf Go types); `sqld-gen-bob` owns the ORM surface. Both are
fully open (sqld and bob are MIT/permissive — nothing paywalled).

## How it works

```
schema.sql + queries → sqld host → IR Catalog
        ├── sqld-gen-go → query rows/params, dynamic queries, AND the shared
        │                 leaf types (enums, composites, domains, RegisterTypes)
        └── sqld-gen-bob → bob models/relationships/where/loaders/joins
                           (Column.Type resolved to sqld-gen-go's shared types)
```

`sqld-gen-bob` maps every column's Go type through the shared `pkg/gotypes`
mapper — the same one `sqld-gen-go` uses — and qualifies enum/composite types
into `sqld-gen-go`'s output package (`typesPackage`). It leaves bob's own enum
generation empty, so a `users.status` column is `db.AppUserStatus` in both the
bob model and the sqld query row.

bob writes its (multi-file) output directly into the plugin's `out` directory
(its generated import paths are rooted there), so this plugin returns no files
to the host — unlike `sqld-gen-go`, which returns file contents.

## Configuration

Run both plugins from one `sqld.yaml`. `sqld-gen-go` owns the leaf types;
`sqld-gen-bob` points at that package via `typesPackage`:

```yaml
plugins:
  - name: go
    binary: ./bin/sqld-gen-go
    out: gen/db
    options:
      package: db
      overrides:
        uuid: github.com/google/uuid.UUID

  - name: bob
    binary: ./bin/sqld-gen-bob
    out: gen/bob
    options:
      package: models
      typesPackage: github.com/acme/app/gen/db   # import path of the gen-go output
      nullMode: pointer                          # MUST match across both plugins
      overrides:                                 # MUST match sqld-gen-go's overrides
        uuid: github.com/google/uuid.UUID
      # factories: true                          # opt-in; see limitations
```

Options:

| option | meaning |
|---|---|
| `package` | Go package name for the models (default `models`). |
| `typesPackage` | import path of `sqld-gen-go`'s output package (where enum/composite Go types live). Required for schemas with UDTs. |
| `nullMode` | `pointer` (default) or `opt`. Selects bob's null wrapping; **must equal `sqld-gen-go`'s `nullMode`** for the structs to interoperate. |
| `overrides` | the same Go-type override table `sqld-gen-go` accepts; **must match** so both generators emit identical types for overridden columns. |
| `models`, `whereLoadersJoins` | toggle those outputs (default on). |
| `factories` | generate bob factories (default **off** — see limitations). |

## Runtime — one pool

bob runs natively on `*pgxpool.Pool` (via `github.com/stephenafamo/bob/drivers/pgx`).
Register `sqld-gen-go`'s custom types on the pool once, and both bob and your
sqld queries inherit them:

```go
cfg, _ := pgxpool.ParseConfig(dsn)
cfg.AfterConnect = func(ctx context.Context, c *pgx.Conn) error {
    return db.RegisterTypes(ctx, c) // generated by sqld-gen-go
}
pool, _ := pgxpool.NewWithConfig(ctx, cfg)

exec := bobpgx.NewPool(pool)              // bob ORM over the SAME pool
user, _ := models.Users.Insert(&models.UserSetter{
    Email:  ptr("a@b.c"),
    Status: ptr(db.AppUserStatusActive),  // shared type
}).One(ctx, exec)

q := db.New(pool)                          // sqld queries over the same pool
row, _ := q.GetUser(ctx, user.ID)
_ = row.Status == user.Status              // both db.AppUserStatus
```

## Limitations (v1)

- **Factories are opt-in.** bob's factories need a randomization expression for
  every column type; bob cannot synthesize one for the externally-owned shared
  types (composites, `uuid.UUID`, `pgtype.*`). Enable `factories: true` only for
  schemas whose column types all have a known random expression.
- **Null-wrapper alignment.** The shared *non-null* leaf types are identical
  across both generators. Nullable fields may differ in wrapper (`sqld-gen-go`
  uses `*T` in `pointer` mode; bob may use `null.Val[T]`). The `opt` null mode
  narrows this; full alignment of nullable wrappers is ongoing.
- **No wasm.** Unlike `sqld-gen-go`, `sqld-gen-bob` ships only as a native binary
  (bob's generator is not a wasip1 target).
- **Queries stay with `sqld-gen-go`.** bob's query-folder codegen is not used —
  sqld owns queries (including the dynamic `@if`/`@orderby` DSL bob can't parse).
